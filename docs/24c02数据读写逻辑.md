# 24C02 里程数据读写逻辑

## 结论

当前 [User/instrument.c](../User/instrument.c) 的里程读写逻辑已在 PC 上用软件模拟的方式验证过：**19 个用例、4857 项检查全部通过**。模拟覆盖了 24C02 的页写回卷、tWR 写周期、掉电撕裂、写坏、总线读失败、环形日志回卷等真实场景，读写逻辑的设计目标（掉电不丢上一条、半截记录绝不被当成有效数据）全部成立。

验证用例同时记录了 2 个**已知边界**（不是缺陷，见文末），以及 1 个可选加固点（上电扫描读失败时的处理）。

验证用的 24C02 软件模拟（芯片模型 + 故障注入 + 用例）只在本机临时使用，按 `.agents.md` 的「测试脚本限制」**不入库**（`.gitignore` 已忽略 `Test/SimEeprom/`）。本文只记录验证方法与结论，代码本身不随仓库分发。

## 存储布局

24C02 共 256 字节，`EEPROM_PAGE_SIZE = 8` 字节一页，共 32 页。里程数据以**环形日志**形式存放：每条记录占 2 页（16 字节），共 16 个槽位（`EEPROM_SLOT_NUMS`），写满后从头覆盖最旧的一条。

| 记录内的字节 | 内容 |
| ------ | ------ |
| 0 ~ 3 | 大计里程（单位 m，小端） |
| 4 ~ 7 | 小计里程（单位 m，小端） |
| 8 ~ 9 | CRC16（CRC-16/CCITT-FALSE，覆盖字节 0~7 和 12） |
| 10 ~ 11 | CRC16 的反码 |
| 12 | 标志位（bit0：是否显示总里程） |
| 13 | 标志位的反码 |
| 14 ~ 15 | 固定标记 `0xA5 0x5A`（提交页写完成的标志） |

前 8 字节组成**数据页**，后 8 字节组成**提交页**，正好各占一个 EEPROM 页——这样每一次页写都不会跨页，符合 24C02 的写限制，也让“数据页先写、提交页后写”的提交协议成立。

## 读写流程

### 上电扫描 `instrument_info_init()`

1. 遍历全部 16 个槽位，逐条读回来做校验（CRC、CRC 反码、标志位反码、固定标记、里程合理范围）；
2. 校验通过的记录里，**大计里程最大**的那条就是最新的一条；大计里程相同时取**小计更小**的那条（TRIP 清零之后写的那条）；
3. 用最新一条恢复 `instrument.total_mileage / subtotal_mileage / is_display_total_mileage`，并把写游标指向它的下一个槽位；
4. 空片（一条有效记录都没有）：里程清零并立刻写一条 `(0,0)`，让下次上电有基准；
5. 扫描过程中出现过总线读失败：不写 EEPROM，保持 RAM 里的 0，避免把原来的里程覆盖掉。

因为“取最大”而不是“取最新物理位置”，任何一条记录被写坏都只是少一个候选，不会让里程倒退或错乱——这也是整个方案能容错的根本原因。

### 保存 `instrument_info_save()`

| 情况 | 写哪里 |
| ---- | ------ |
| 里程变了 | 写环游标指向的槽位，写成功后游标 +1（末尾回到 0） |
| 里程没变、只有显示模式变了 | 原地重写上一次写的那一槽 |

原地重写是为了避免日志里出现“里程相同、显示模式不同”的两条记录（上电扫描无法判断哪条更新）。

一次保存的顺序是：**数据页 → 提交页 → 回读校验 → 推进游标**。任何一步失败都直接返回，游标和 `last_*` 都不更新，下次保存重写同一个槽位，不会在日志里留下坏记录或跳过槽位。

### 保存时机

`mileage_scan()` 在走满 `MILE_SAVE_DISTANCE`（100 m）且距上次保存超过 `MILE_SAVE_MIN_INTERVAL`（100 ms）时调用 `instrument_info_save_enable()`；停车持续 `MILE_STOP_SAVE_TIME`（2 s）会把零头补写一次。`instrument_info_save_enable()` 只是启动一个 `INSTRUMENT_INFO_SAVE_TIME`（100 ms）的延时，到点后由主循环的 `instrument_info_save_handle()` 真正写入——把“判断 + 清零”放进临界区，避免中断把一次保存请求清掉。

## 掉电撕裂分析（已验证）

一帧 16 字节分两次页写，任意位置掉电的结果：

| 掉电位置 | 芯片状态 | 上电结果 |
| ----- | ----- | ----- |
| 数据页中间 | 数据页残缺，提交页仍是空片/上一条的 | 本条无效，用上一条 |
| 数据页写完、提交页没写 | 新数据 + 旧 CRC | CRC 对不上，本条无效，用上一条 |
| 提交页写了 1~5 字节 | CRC / 反码 / 标志位不完整 | 本条无效，用上一条 |
| 提交页写了 6 字节及以上 | CRC、反码、标志位、标志位反码都已写全（固定标记内容不变） | 等价于写完整，本条有效 |
| 16 字节全部写完 | 完整记录 | 本条有效 |

在“原地重写”场景下，数据页写的字节和原来完全一样，所以提交页一个字节都没写时旧记录依然自洽（有效，只是显示模式没改成功），只有提交页写了中间几个字节才会退回上一条。

## 软件模拟验证

### 模拟方式

模拟做在**软件 IIC 总线**这一层（`iic_soft_write / iic_soft_read / iic_soft_wait_ready`），因此被测的 [Hardware/eeprom_24cxx.c](../Hardware/eeprom_24cxx.c)（跨页保护、参数检查）和 [User/instrument.c](../User/instrument.c) 都是**原样参与编译，一个字节都没改**。

- 芯片模型：256 字节、页大小 8、页写时地址在页内回卷、顺序读地址自动递增、掉电不丢数据；
- 故障注入：写失败（内容不变）、页写撕裂（只写进去前 n 字节后掉电）、写“成功”但某字节没写对、总线读失败、等 tWR 超时；
- 上电重启：把 instrument.c 里的静态变量复位成上电初值后重跑 `instrument_info_init()`（所以验证程序是用 `#include` 方式包含被测源文件的白盒写法，为了能复位 static 变量）；
- 参考实现：另写了一份独立的记录解析/构造代码，用公开测试向量 `CRC-16/CCITT-FALSE("123456789") == 0x29B1` 交叉校验。

### 变异测试（验证“验证工具”本身有效）

为了确认这套用例真的能发现问题，临时向 [User/instrument.c](../User/instrument.c) 注入 7 种典型缺陷，每次跑完都还原（还原后文件校验和与原来一致）：

| 注入的缺陷 | 是否被发现 |
| ----- | ----- |
| 去掉 CRC 重算校验（只留 CRC 反码） | 是（4 个用例、346 项检查失败） |
| 上电扫描改成取里程最小的记录 | 是（14 个用例、108 项检查失败） |
| 去掉回读校验 | 是（1 个用例、4 项检查失败） |
| 数据页写失败也推进游标 | 是（16 个用例、198 项检查失败） |
| 原地重写判据取反（里程一变就覆盖最后一条） | 是（12 个用例、145 项检查失败） |
| 扫描时 TRIP 比较方向取反 | 是（1 个用例、2 项检查失败） |
| 上电扫描读失败时仍然写 EEPROM | 是（2 个用例、2 项检查失败） |

“先写提交页、再写数据页”这种顺序调整没有被用例判为错误——因为 CRC 覆盖了数据页，两种顺序在掉电时都只能得到“记录有效”或“记录无效”，不会产生半对的数据，属等价实现。

## 已知边界与建议

1. **上电扫描读失败（可选加固）**：`instrument_info_init()` 读失败时不写 EEPROM，但 RAM 里是 0。主循环随后 100 ms 就会保存一次 0，写到槽位 0。只要全片还有别的有效记录，下次上电会从最大值恢复（用例 10 已验证自愈）；极端情况下（全片只剩 1 条记录）这条记录会被 0 覆盖（用例 11 记录了该行为）。如果这道防线也要补上，可以在扫描失败时置一个 flag，`instrument_info_save()` 之前检查它（或先重试扫描 2~3 次），代价是多一个全局标志。
2. **原地重写时掉电会退回上一条记录**：只改显示模式时是原地重写，若掉电正好落在提交页中段，这一槽作废，上电会退回上一条记录，最多损失“上一条记录到当前记录之间新增的里程”（也就是上一次新槽位保存之后的增量）。数据页字节本身没变，所以不会出现“半对”的数值。
3. **磨损估算**：每走 100 m 保存一次，每次写 2 页，16 个槽位轮转 ⇒ 每页平均每 1600 m 写一次。按程序限制的 80 万次/页算，约 128 万 km 才会耗尽，寿命不是瓶颈。
4. **掉电最多丢多少里程**：保存间隔 100 m + 100 ms 延时 + 100 ms 最小间隔，200 km/h 时约 5.6 m/100 ms，最坏约丢 110 m。
