# 中断共享变量的原子访问

## 结论

`volatile` 不能保证原子性。它主要用于要求编译器按程序要求实际访问变量，避免把可能由中断修改的值长期缓存到寄存器；它不保证多字节读写不可被打断，也不把“读取、判断、清零”合成一个不可分割操作。

本工程使用 Keil C51/MCS-51。`battery_scan_time_cnt` 是 `volatile u16`，由 TMR1 中断递增、主循环读取并清零。MCS-51 是 8 位内核，16 位变量通常需要多次字节访问，因此主循环可能读到撕裂值；此外，即使读值碰巧完整，中断也可能发生在判断和清零之间，导致新增加的计数被清掉。

因此，当前这种共享方式可以使用，但必须把主循环侧的复合操作保护起来。仅把变量声明为 `volatile`，或只保护单独的赋值，都不够。

## 当前代码的竞争窗口

```c
if (battery_scan_time_cnt < BAT_SCAN_PERIOD) {
    return;
}
battery_scan_time_cnt = 0;
```

例如，主循环读到计数已达到周期；在主循环写入 `0` 之前，TMR1 中断又递增了一次；随后主循环清零，新的一次计数就丢失了。由于计数器是 16 位，`if` 中的读取本身也可能与中断更新交错，形成高、低字节来自不同时间点的值。

## 推荐：短临界区内完成检查和清零

本工程芯片头文件将全局中断使能位定义为 `IE_EA`。在主循环中保存原使能状态，短暂关闭中断，在同一个临界区里检查并清零，最后恢复原状态：

```c
void bat_scan(void)
{
    u16 adc_val;
    u16 voltage;
    u8 irq_was_enabled;
    u8 scan_due = 0;
    static u8 is_initialized = 0;

    irq_was_enabled = IE_EA;
    IE_EA = 0;
    if (battery_scan_time_cnt >= BAT_SCAN_PERIOD) {
        battery_scan_time_cnt = 0;
        scan_due = 1;
    }
    IE_EA = irq_was_enabled;

    if (scan_due == 0) {
        return;
    }

    /* 后续 ADC 平均、换算和电压滤波逻辑保持不变 */
}
```

重点：

- **检查和清零必须在同一临界区内。** 不要先在区外检查，再关中断清零。
- **恢复进入临界区前的状态。** 不要退出时无条件写 `IE_EA = 1`，否则调用者原本关闭了中断时，会被意外打开。
- **临界区要尽可能短。** 只包住共享状态操作，不要把 ADC 计算、滤波、打印等放在关中断期间。
- 上例只适合在可使用 `IE_EA` 的普通主循环上下文中。若临界区可能从另一个中断上下文调用，应使用项目/芯片明确支持的嵌套临界区方案。

把全局中断短暂关闭会延迟所有中断。若确实需要只屏蔽 TMR1，应保存并恢复对应的中断使能位，并按芯片头文件核对中断号与寄存器映射；不要直接“关闭后再无条件使能”。

## 其他常见方案

### 原子快照

若主循环只需要读取 16 位计数而不清零，可在短临界区内复制到局部变量，随后在开中断状态下计算：

```c
u16 tick_snapshot;
u8 irq_was_enabled;

irq_was_enabled = IE_EA;
IE_EA = 0;
tick_snapshot = shared_tick;
IE_EA = irq_was_enabled;

/* 使用 tick_snapshot 进行比较或计算 */
```

这种做法只保证快照一致，不会自动解决主循环消费事件时的并发问题。

### 消费一个周期并保留余数

如果系统需要保留超过一个周期的部分计数，可在临界区里读取计数，并在到期时减去一个周期，而不是清零：

```c
u16 elapsed;
u8 irq_was_enabled;

irq_was_enabled = IE_EA;
IE_EA = 0;
elapsed = battery_scan_time_cnt;
if (elapsed >= BAT_SCAN_PERIOD) {
    battery_scan_time_cnt -= BAT_SCAN_PERIOD;
}
IE_EA = irq_was_enabled;

if (elapsed < BAT_SCAN_PERIOD) {
    return;
}
```

这会保留周期余数，但如果主循环长时间阻塞，恢复后可能连续处理多次到期任务。是否需要追赶，应由业务决定。若采用此法，还应明确计数器饱和/回绕策略。

### 单字节事件标志

若业务只关心“至少发生过一次”，可以让中断设置一个 `volatile u8` 标志，主循环消费标志。单字节访问在 8 位内核上通常可由单条访问完成，但“检查后清零”仍是复合操作，若要求不丢事件，消费动作仍需临界区或可靠的原子交换机制。标志还会合并多个事件，不能替代需要精确累计次数的计数器。

## 对本例的建议

电池扫描是低频周期任务，当前 16 位饱和计数器可以保留；建议采用“短临界区内检查并清零”的写法。`volatile` 继续保留，用于表达中断与主循环共享关系，但不要把它当作原子性保障。若今后要共享其他多字节数据，也采用原子快照或项目统一的临界区封装，并检查读、写、清零及读改写是否整体受到保护。
